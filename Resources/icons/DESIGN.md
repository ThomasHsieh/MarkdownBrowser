# App 圖示

深灰圓角方塊上一本翻開的書：象牙白內頁、暖橘書封，左頁是 Markdown 的 `M`、
右頁是向下箭頭，每頁下方兩道短線，其中一道是橘色。

顏色跟閱讀介面同一組：深灰是專注，紙白帶出文字的溫度，`#DD9853` 的橘是
「這裡值得停留」—— 也就是內文裡粗體的那個橘。符號只有 `M` 與箭頭，沒有字。

## 檔案

| 檔案 | 角色 |
|---|---|
| `AppIcon-v2.png` | **母圖**，1254 px。唯一的來源，要改圖示就換這一張 |
| `AppIcon-v2.prompt.txt` | 產生母圖用的提示詞，留著方便重做或微調 |
| `AppIcon.png` | 從母圖算出來的 1024 px 標準母版，供預覽 |

`AppIcon.png` 與 `AppIcon.icns` 都是 `make icons` 產生的，不要手動改。

## make icons 在做什麼

兩件事，其餘交給系統工具：

**校正幾何：滿版，而且要是方的。** 先用 alpha 量出母圖裡圓角方塊的實際範圍，
裁出來、把自己的圓角補成直角，再拉滿整個畫布。

補直角的做法是逐列沿用邊緣像素的顏色往外延伸 —— 方塊是深灰的垂直漸層，
用整片單色填會在上下兩端看得出色差。母圖的方塊是 1090×1075 不是正方，
所以用 Lanczos 的 `aspectRatio` 分別拉到寬高都等於畫布；1.4% 的形變看不出來。

會這樣做是因為 macOS 26。它的 Dock 會把舊格式的 `.icns` 墊到系統自己的底板上
再套遮罩，於是：

- 留白版（傳統的 824/1024）→ 變成「板中板」，淺灰底板中間一個縮小的深色方塊
- 撐滿但自己帶圓角 → 圓角比系統遮罩圓，四個角露出底板的灰邊，像一圈光暈

補成直角之後，圓角完全交給系統遮罩切，Dock 裡就跟其他 App 一模一樣。
alpha 最後統一壓成 1：Lanczos 與 unsharp 會留下 252 這種尾數，差 3/255
就足以讓底板從邊緣透出來一點。

（在 macOS 26 之前，留白＋自帶圓角才是對的。這裡是照著實機 Dock 的樣子決定的。）

**把背景壓平。** 母圖的背景是從 `#4D4F51` 一路壓到 `#0E1112` 的大幅漸層，
上緣偏亮、下緣是烘進去的陰影，一小塊背景裡就有上千種顏色 —— 在 Dock 上看起來髒。
原生圖示（例如 Obsidian）的底幾乎是全平的 `#1F1F1F`→`#191919`。

做法是把每一列往內一點的像素當成「這一列的背景色」（書本置中，左緣一定是背景；
取樣要避開最外緣那圈偏亮的鑲邊，否則真正的背景會被當成內容留下來），再依每個
像素與它的差距決定換掉多少：差距小＝背景，換成新底色 `#202020`→`#181818`；
差距大＝書本，原樣保留；中間用 smoothstep 平滑過渡，邊緣才不會出現鋸齒。
書本落在紙面下方的接觸陰影比背景暗得多，會被判定成內容而留下來。

**縮圖用 Lanczos，不用 AppKit 的 `.high`。** 母圖是立體算圖，縮到 32–64 px
時 `.high` 內插明顯偏軟，在 LaunchBar 那種小圖清單裡看起來就糊。改用
CoreImage 的 `CILanczosScaleTransform`，64 px 以下再補一點 `CIUnsharpMask`
（強度 0.35 —— 再上去圓角方塊邊緣會浮出一圈黑色光暈，比糊還醜）。

**打包交給 `iconutil`。** 不要手刻 ICNS 容器：手刻版本會把 16／32 px 掛在
`icp4` / `icp5` 這兩個 OSType 上，而它們塞 PNG 是不可靠的 —— macOS 有解碼
路徑會當成原始點陣資料，解出來是一片彩色雜訊，偏偏大尺寸正常，很容易漏看。
